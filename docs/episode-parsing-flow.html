候选链接 → 季数/集数识别 全流程

MediaTrack fast path 从 PanSou 搜索到落盘归位，每一步的季/集数识别逻辑、优先级与守卫机制。

候选获取 PanSou API

用目标剧名（或别名兜底）搜 PanSou，返回 候选列表：每条 = {id, title, url}。

兜底：裸标题无结果 → 依次用 aliases[]（英文原名 → 繁体 → 简体）重搜，最多 3 轮（MAX_FALLBACK_SEARCHES）。

A/B/C/D 评分 纯代码，零 LLM

逐条候选按 candidate-grader.ts 的纯函数评分，四条规则链：

等级条件含义
D标题不匹配（normalize 后无交集）永不尝试
C命中目标但带 电影版/真人版/OVA/特别篇（同名异作）疑似同名异作
C季号不匹配：标题里的季号 ∉ 任务季范围别季包，不尝试
B标题命中 + 季号对，但缺 中字 标记或缺集数/全集证据可疑但可能
A标题命中 + 季号对 + 中字 OK + 有集数/季号/全集证据top 是 A → 代码按分数直选，零 LLM（PR #45：多个 A 也不走仲裁）
季号识别 5 种形态： 第N季 / Sxx / Season N / 3.全集（隐形季号，紧贴「全集/合集/完结」） / 1-10季（范围，只降级不给 A 级证据）。 范围不含目标季 → C；含目标季 → 维持 B。
集数证据标记： SxxExx 或 第N集/期 → 有具体覆盖证据 → 加分。 全集/complete/更新至 → 全集标记 → 加分。
选片决策

评分结果只有两种分支：

top 是 A 级 → 代码直选（零 LLM）

  • uniqueTopGrade = graded[0].grade === "A"
  • PR #45：多个 A 不触发仲裁，代码按分数（base + 中字 + 画质 + 季号）取最高
  • 直接转存该候选；转存失败（未覆盖/死链）再换下一个 A

无 A 级（top 是 B/C/D）→ AI 仲裁

  • 升级 AI 选片仲裁 arbitrator
  • AI 可在 ≤3 个候选中多选或放弃
  • 兜底池：≤1 次 AI 挑选
转存落盘 transferCandidate

选定候选后调用网盘执行器（115 / 夸克 / 光鸭 / 天翼 / 123），把资源转存到暂存目录。

返回：staging[] = 落盘后的文件列表，每条含 {id, path, isVideo, isSubtitle, sizeBytes}。

死链：0 个落盘文件 → 不计入转存预算，直接换下一候选（≤10 次死链探测）。

暂存区解析 digestStaging() 单次解析台账

这是 唯一的解析入口（2026-09-13 重构）：所有下游（归位、改名、日志）都查 digest.parsed 台账，不再各自裸解析。

2026-09-13 之前：入库链有 5 处独立调用 episodeCodeFromPath， 漏传 episodeNames 导致 digest 认 3 集、归位只落 1 集、解析明细全写同一集号 （花儿与少年 S8 四次实测）。现在分叉点物理消失。

逐文件流程：

  1. 附件判定： basename 命中 sample/花絮/预告/广告/making/MV/OST → junk=true，不参与集号解析
  2. 覆盖表优先： 查 overrides[video.path] 或 overrides[base]（AI 映射结果）
  3. 裸解析： 无覆盖 → episodeCodeFromPath(path, seasons, episodeNames, rules)
  4. 年守卫： 解析出 code 后 → episodeDateConflict(code, fileName, airDates)：文件名内嵌日期与 TMDB 播出日差 >45 天 → 不采信

覆盖判定：

  • episodeCodes[] = 去重后的解析结果
  • coveredCodes[] = 解析结果 ∩ needCodes[]
  • missingCodes[] = needCodes[] − episodeCodes[]
  • outOfSeasonCodes[] = 解析出但季号不在任务范围内
  • passes = 全量覆盖缺集（issue #44：部分覆盖不再收尾）
集数解析 episodeCodeFromPath()

两级解析，优先 basename，其次路径归季：

① 直接解析 basename

调用 episodeCodeFromFileName(basename, seasons, episodeNames, rules)

自带季号的规则（SxxExx/变体/1×01）始终可用；无季号规则仅单季可用。

→ 命中 → {code, seasonSource: "basename"}

② 多季：路径归季

仅多季任务（seasons.length > 1）才走此路。

seasonFromPathSegments() 扫描目录 segment：

  • Season N / S0N / S N
  • 第N季 / N季（含中文数字）
  • 01/ 纯数字（仅当在任务季范围内）

找到后以该季为单季上下文重新解析 basename。

→ 命中 → {code, seasonSource: "path"}

文件名解析优先级 episodeCodeFromFileName()

6 条内置规则 + 自定义规则，按顺序执行，首个命中即返回。

# 规则名 自带季? 单季限定? 正则示例 示例
0 SxxExx 是 否 [Ss](\d{1,2})[Ee](\d{1,4}) 狂飙.S01E01.1080p
1 变体 是 否 [Ss](\d{1,2})\s*[. ]\s*[Ee](\d{1,4})(?!\d) S01.E01 / s01 e01
2 1×01 是 否 (?:^|[^A-Za-z0-9])(\d{1,2})\s*[x×]\s*(\d{1,4}) 01x01 / 1×03
3 E01 / EP01 否 是 [Ee][Pp]?\.?\s*(\d{1,4}) Ep.12 / E03
4 第N集/话/期 否 是 第\s*(\d{1,4})\s*(?:集|话|話|期) 第01集 / 第8话
5 纯数字 否 是 ^(\d{1,3})$（剥扩展名后整名） 01.mp4 / 15.mkv
6 自定义规则 取决于 role 取决于 role 用户配置的正则 issue #44
多季任务禁用规则 3/4/5： 无季号规则（E01 / 第N集 / 纯数字）在 seasons.length > 1 时全部禁用 —— 季不明不猜，交给仲裁。 这正是 if (singleSeason) 闸门：多季流程的第一步（全表解析）返回 null， 第二步 episodeCodeFromPath 的路径归季才有机会跑。 ⛔ 删了会退回全表锚定 → 多季包「代码识别 0 集」复发。
数字守卫 isPlausibleEpisodeNumber()： 合理范围 1–999；排除分辨率（1080 / 2160 / 4320 / 720）；纯数字规则额外排除年份 1900–2099。 长篇动漫允许 4 位集号（One Piece 1000+ 集）。
综艺「第N期」Part 锚定 anchorVarietyPeriod

综艺一期在 TMDB 可能拆多集（第10期 = Episode 10 (Part 1) + (Part 2)），机械 E(N) 会系统性错位。

锚定流程：

  1. 文件名命中 第N期 → 提取期号 N
  2. 提取文件名部分标记：第N期上 → 上、第N期（中） → 中、第N期下 → 下
  3. 查 episodeNames（TMDB 各集原始 name）找期号 = N 的所有集
  4. 从 TMDB 名提取部分号：英文 (Part 1) / -1、中文 第N期上
  5. 按 上=0, 中=1, 下=2 排序，文件名标记按下标对齐

TMDB 集名六种真实形态（2026-09-13 线上实测）：

语言形态示例
en-USEpisode 1 (Part 1)地球超新鲜 S1/S2
en-USEP1-2花儿与少年 S8（一期三部分）
en-USEP1花儿与少年 S7（不分）
en-USEpisode 1中餐厅（无部分）
zh-CN第1期上：王星越…花少 S8 一期三部分
zh-CN第1期：龚俊…花少 S7 不分与拆分混用
zh-CN 是 TMDB 默认语言：只认英文 EP1-1 会让锚定在线上整季失锚 （2026-09-13 花少 S8 案：DB 里存的是「第1期上：…」，老正则 /ep…\d/ 一个都匹配不到）。
衍生内容黑名单（规则 4 专属）： 「第N期」命中 加更/直拍/手记/纯享/花絮/坦白局/送机/PV/bonus/cut 等 token → 不给集号（衍生内容不计入覆盖）。黑名单只跟「期」走；挡「期」后回退再测「集/话」防误伤。
年守卫 episodeDateConflict() 45 天容差

文件名内嵌完整日期（2025.08.29 / 2025-08-29 / 20250829 / 2025年8月29日） 与该集 TMDB 播出日（episode_states.air_date）差 >45 天 → 不采信这个集数。

典型场景：「1-10季」合集包实际落的是第九季（2025 日期）的文件， 在 S10 单季任务下被解析成 S10Exx —— 号码对、季份错。 文件日期 2025 vs TMDB 播出日 2024 → 差 >45 天 → 拒收。

惰性规则：文件名无日期 → 守卫不触发；该集播出日未知（TMDB 未返回）→ 守卫不触发。

覆盖判定与收尾

✅ digest.passes = true

全量覆盖缺集 → 直接 finalizeLanding()：

  • 改名：Title.SxxExx.ext（内置正则，不走台账）
  • 归位：移动到 Season N/ 目录
  • 标记：episode_states 已入库
  • 清理暂存区

→ 零 LLM，fast path 收尾

⚠️ digest.passes = false

未全量覆盖 → 升级 AI 集数映射 arbitrator

  • 把全部落盘视频减衍生内容交 AI
  • AI 只给 fileName → SxxExx 映射
  • 代码校验：文件名存在 / 集号不重复 / 期号一致
  • 通过 → 重建 digest → finalize
  • 不通过 → 清暂存，换下一候选

换候选后的兜底链：

  1. primary 池代码路径转存（≤10 次）
  2. primary 池 AI 挑选（≤3 次，独立子预算）
  3. 别名兜底重搜（≤3 轮关键词，仅 primary 无 A 时启动）
  4. 兜底池代码路径转存（≤5 次）
  5. 兜底池 AI 挑选（≤1 次）
  6. 尾部重转：两池耗尽后按覆盖数降序重转 top-3（防分享过期轮换）
  7. pending 收尾 → 或诚实报告 reportNoCoverage，下次巡检再来
pending 积累与多季互补 retry_other → onPartial

每次 digest.passes = false（未全量覆盖）时，wipe staging 之前先把已识别的集数搬到 pending 目录（ctx.pendingEntries Map）。所有候选试完后，pending 里攒的集数统一 finalizeFromPending() 落库。

新主力（count > bestCount）

新候选覆盖集数比之前最多 → 换主力：

  • 多季互补（2026-09-12）：只删除 pending 中与新候选撞码的旧条目
  • 不撞码的旧条目保留（不同候选覆盖不同季）
  • 新候选的覆盖集写入 pending + moveToPending() 搬文件

旧逻辑无条件清空所有旧条目 → 多季任务 40 集只落 20

补充（count ≤ bestCount）

新候选覆盖集数没超过主力 → 只补唯一码：

  • pending 里已有的 code → 跳过
  • pending 里没有的 code → 新增条目 + moveToPending()
  • 日志：补充: N 集
finalizeFromPending（pending 收尾）：所有候选试完后，ctx.pendingEntries.size > 0 → 调用 finalizeFromPending()，对每个 pending 条目执行 rename → 归位 → mark， 一次性入库。失败 → 降级到 reportNoCoverage。
已知 gap（2026-09-13 run bf43a1d1）：多季 pending 积累最优候选可能丢 —— 候选 3 识别出 20 集但 pending 三行日志全无，20 集被丢。机制未定位，别在没查清前改 tv.ts onPartial。
