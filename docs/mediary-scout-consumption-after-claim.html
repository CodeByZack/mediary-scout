6½pending 积累 · 部分覆盖暂存

每轮收口判定 retry_other（未全量对齐）时，先把当前候选认出的缺集文件从 staging 搬进 pending 目录（在 wipe 之前，B1 修复），再清暂存换候选。

多轮候选的识别结果按 code → fileId 累积在 pendingEntries：
· 覆盖数超过当前主力 → 新主力：删掉旧主力的 pending 文件、整体替换；

落地收口 · LandingVerdict 状态机

fast-path/landing.ts · closeOutTvLanding

一个候选的落地回合收敛为六种判定。done 非空 = 本轮终局，调用方直接 return；done = null 用 next 继续循环。 TV 没有落盘诊断仲裁——未全量对齐即清暂存换下一个候选（§43 全量对齐才落盘）。 但部分覆盖不再白丢：retry_other 换候选前把已识别文件搬进 pending（见 D 区 6½），候选耗尽后 finalizeFromPending 统一归位（issue #53）。

回环 retry_other / dead 都不产生 done：循环取 nextCandidate(grading, tried) 继续；池内无下一候选则退出本池 → primary 试尽后落阶段 2 兜底 → 两池都耗尽才走 诚实终止。

映射三重校验（代码，不信任 AI）

① 文件名必须在本次落盘的全部视频清单里（防幻觉文件名）；

② 一个集数最多被映射一次（重复 code → 整表作废）；
③ 期号一致性：文件名里的「第M期」与该集 TMDB 集名里的 Episode N 不符 → 整表作废（防 AI 把不存在的期硬安上最新集号迎合 need）。
无 episodeNames 时第 ③ 条惰性。
landing.ts:52–205

两个不校验的东西（有意为之）

映射校验不看 code 形状（SxxExx）、也不看季与任务是否匹配。

单季任务下越季 code 会被 digest 的 need 集合运算自然排除（need 只含目标季的 SxxExx），不会误入库——但没有显式闸门。
多季任务 AI 看完整路径（path 含文件夹季信息，seasonFromPathSegments 归季），映射未全量对齐同样处理。

「no」不冒领 AI 归因

"no"（movie / 代码已全覆盖 / 全衍生文件）一次 AI 都没跑：

escalated 不得虚增，结账行不得写「AI 介入」。
反之也绝不能在这里赋 false——它可能已带选片仲裁置的 true，覆盖会让 runCheckout 谎报零 AI。

硬预算 fast-path/budgets.ts

  • primary 池真实转存 ≤ 5（MAX_TRANSFER_ATTEMPTS，2026-09-10 由 10 下调）
  • 兜底池独立转存 ≤ 5（MAX_FALLBACK_TRANSFER_ATTEMPTS）——primary 全废兜底照样有配额
  • 死链探测 ≤ 10（MAX_DEAD_LINK_RETRIES）——不占转存预算，跨两阶段共享（狂飙 45 候选的教训）
  • 别名兜底重搜 ≤ 3 轮（MAX_FALLBACK_SEARCHES）——保护共享 PanSou 配额
  • 队列侧退避重入队 ≤ 3 次，1min / 5min / 15min
  • 孤儿恢复重入队 ≤ 5 次（防毒任务跨重启无限循环）
  • 单 tick 排空 ≤ 50 个 run

AI 升级点（单次调用、无工具）

  • 选片 arbitrateSelection：无唯一 A → 挑一个或放弃（TV / movie 各一款）
  • 集数映射 arbitrateEpisodeMapping：TV（单季/多季）代码解析未覆盖 need → 把全部落盘视频减衍生内容交 AI 映射（多季用完整路径归季），只给映射不定收否（收否仍由 digest 客观判定）
  • movie 诊断 arbitrateMovieDiagnosis：落盘不像一部正片 → accept / retry_other / abandon
  • 回复解析失败一律保守降级；TV 没有落盘诊断仲裁（§43）
  • 已知 gap：arbitrateDiagnosis（TV 版）零调用方，issue #43 待清

落地判定（六种 verdict）

  • clean / mapped_clean → finalize 落库（改名 + 归位 + mark）
  • dead → 死链探针换候选；systemic → 立即终止，不硬磨
  • retry_other → 未全量对齐就不落盘：清暂存换候选（§43）
  • abandon → 归位异常，wipe 后诚实未覆盖
  • 候选/预算耗尽 → reportNoCoverage：诚实未覆盖，下次巡检再来

为什么是这条路径

  • 旧 agent 每步重发完整 system prompt（4–6k）+ 工具定义（4–8k）≈ 固定 ~10k tokens/请求，60 步 × 每天巡逻 N 部剧 → 月度账单线性放大
  • LLM 从「60 步工具循环的司机」降级为「最多三次单点裁判」，干净路径零 LLM（P1 / P3 已落地）
  • 已知 gap：搜索配方序列（裸标题 → 繁体 → 英文换词）未接进快路径——裸标题搜不到就直接放弃；qualityPreference 被快路径忽略，只看候选标题里的画质 token
